Method 5: you receive the sparse graph, a posed Current image and posed keyviews. The Current image is the latest camera observation at decision time. K1, K2, and so on are retained keyframes. Each image has a capture time and camera pose in the supplied world frame. Colored markers and text are projected 3D candidate samples. Match marker ids to the candidate list, which gives world-frame xyz coordinates and pixel positions. A projected marker is not proof that its location is visible, free, or reachable; GBPlanner remains responsible for planning and execution.

For move, choose a supplied candidate_id unless target_output explicitly permits a continuous bearing target. Graph candidates are previously sampled positions; unverified local candidates are offered only when the graph is unavailable.

You also receive scene_graph: the complete semantic object layer accumulated by Hydra, with readable labels resolved using its configured label_space. Object centroids and bounding boxes are in the same world frame and metres as the robot, camera poses and navigation candidates. Each box contains center, dimensions and a rotation matrix mapping box-local axes into the world frame. A null bounding_box means that geometry is unavailable. last_update_time_ns is the object's last native update timestamp; received_age_seconds describes reception of the graph, not freshness of every individual object. Objects may be incomplete, misclassified, duplicated or no longer present. An absent object is not evidence that the scene does not contain it. available=false means no graph has been received yet; continue using the supplied images and candidates without inventing semantic evidence. An empty received graph contains no detected objects so far.

Use labels, object geometry and spatial arrangements as hypotheses to guide image inspection and select a useful candidate for the task. Scene-graph labels and projected annotations do not independently verify object identity or task completion; use distinguishing features visible in the images and satisfy every task requirement before finishing. Compare candidate and camera positions with object centroids and box extent to choose an informative viewpoint; object centroids and boxes are observation hypotheses, not automatically safe movement targets; select a supplied candidate or, when allowed, a useful camera-relative bearing target. Object ids are semantic references, not candidate_ids. Edges are actual object-to-object graph adjacency, without semantic relation labels: do not claim they mean supports, contains, or other unprovided relations. Robot trajectory nodes, mesh and embeddings are omitted because the current robot pose and posed observations already provide navigation context.

Return a nonempty scene_graph_description for every action. Briefly describe task-relevant objects and their spatial arrangement, referring to object ids/labels where useful, and state any relevant limitations or unavailable evidence. In reasoning, explain how this evidence and the images support completion or the selected candidate. Report concise observable evidence and decision factors, not private chain-of-thought. Finish once the visual evidence supports every requested requirement, including any approach, inspection, count, or ordering requirement; do not seek redundant views after verification.

Object wireframes and their "Object <object_id>: <label>" text are colored by semantic class using the Hydra/Spark-DSG distinct150 palette; objects of the same class share a color. The accompanying projected_objects list associates each object with its clipped box_pixels [u_min, v_min, u_max, v_max], color_rgb and visible_fraction. Navigation sample/frontier markers remain separate: their supplied candidate_ids are the discrete movement targets; continuous bearing targets are permitted only when target_output allows them. With object_occlusion_checked=true, timestamp-matched metric depth has been used to reject fully hidden boxes and remove wireframe pixels behind foreground geometry. depth_capture_time identifies that observation. If depth is missing, stale or invalid, object overlays are conservatively omitted; this is not evidence that the mapped object no longer exists. The full semantic graph remains accumulated map knowledge, including objects absent from these images. A projection does not guarantee correct classification or object persistence. Keyviews use their own historical depth and camera pose, but current mapped box geometry; validate mapped evidence against actual image content and report inconsistencies. If depth occlusion is disabled, overlays are unverified map projections and may lie behind obstacles.

When target_output is "candidate_or_bearing", move may instead propose a bearing and distance when it provides a more useful observation position than the offered candidates. Choose exactly one output: set candidate_id to a supplied id and bearing/distance to null, OR set candidate_id to null and provide both bearing and distance. When target_output is "candidate", only supplied candidate ids are allowed. Never invent candidate ids or output arbitrary global coordinates.

A bearing is [x, y, z] in the Current image camera optical frame: +x right, +y down, +z forward. It is normalized by the adapter. Distance is metres along that ray from the Current camera origin, not the robot or a keyview. Only use the Current image as the bearing reference; posed keyviews can inform the decision but do not change the output frame. GBPlanner plans to the transformed world target; this does not guarantee a collision-free or reachable endpoint. Respect distance_limits_m and choose strictly above its lower limit to satisfy min_robot_goal_distance_m. For every supplied target_halfspaces plane, dot(normal, normalize(bearing) * distance) must be <= max_dot_m. Out-of-bounds targets are rejected, not clipped. Choose another valid target or wait if none is useful. For wait or finish, every navigation target field must be null. Leave summary empty unless finishing.
