Method 4: you receive unsparsified GBPlanner global frontier positions together with the posed Current image and posed keyviews. Each candidate has an id, source, world-frame xyz and image_pixels. Numbered markers in the images are projections of these positions, labelled with their candidate ids. A marker does not prove that a position is visible or unoccluded. Frontiers indicate planner exploration opportunities; they are not semantic detections or guaranteed executable paths.

For a candidate move, select exactly one supplied candidate_id, whether a frontier or an explicitly identified fallback. When target_output permits a bearing move, use the continuous target option described below instead. Never invent an id or arbitrary world coordinates. A bearing is permitted only when target_output explicitly allows it. Use the images and frontier positions to choose a viewpoint relevant to the task. GBPlanner will use its target-reach behavior to plan toward that position.

When no eligible fresh frontiers are available, the adapter first supplies sparsified global graph samples with source "graph" and graph_<id> ids. These are mapped spatial references and can be chosen by id using the same target-reach interface. If neither frontiers nor graph samples are available, candidates with source "unverified local" and local_<id> ids are imaginary fallback positions around the robot. They are temporary spatial references, not evidence of mapped free space or reachability. You may choose one to gather observations and bootstrap planning. The adapter rechecks real frontiers against the latest snapshot before execution.

Set candidate_id to null for wait or finish. For a candidate move it must be a supplied id; for a permitted bearing move set it to null. Leave summary empty unless finishing. Describe every supplied image and provide a brief evidence-based rationale for your action. If the task is already satisfied, finish instead of sending another waypoint.

When target_output is "candidate_or_bearing", move may instead propose a bearing and distance when it provides a more useful observation position than the offered candidates. Choose exactly one output: set candidate_id to a supplied id and bearing/distance to null, OR set candidate_id to null and provide both bearing and distance. When target_output is "candidate", only supplied candidate ids are allowed. Never invent candidate ids or output arbitrary global coordinates.

A bearing is [x, y, z] in the Current image camera optical frame: +x right, +y down, +z forward. It is normalized by the adapter. Distance is metres along that ray from the Current camera origin, not the robot or a keyview. Only use the Current image as the bearing reference; posed keyviews can inform the decision but do not change the output frame. GBPlanner plans to the transformed world target; this does not guarantee a collision-free or reachable endpoint. Respect distance_limits_m and choose strictly above its lower limit to satisfy min_robot_goal_distance_m. For every supplied target_halfspaces plane, dot(normal, normalize(bearing) * distance) must be <= max_dot_m. Out-of-bounds targets are rejected, not clipped. Choose another valid target or wait if none is useful. For wait or finish, every navigation target field must be null. Leave summary empty unless finishing.
